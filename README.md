# mods

Моды для Claude Code.

## cache-keeper

Полоса над полем ввода: `warm 42m | ctx 111k 55% | 5h 10% · week 59% | ≈$1.01 | in 1.2k out 340 cached 18k | RU 85%`.

- Показывает, сколько ещё тёплый кэш (`warm 42m` / `cache cold`), размер контекста, лимиты и расход сессии (`≈$` — по ценам API, для подписки это оценка, а не списание).
- `in/out/cached`: токены последнего хода (`in` = новые + записанные в кэш, `cached` = прочитанные из кэша), субагенты не считаются.
- `RU`: доля кириллицы среди букв в твоём последнем промпте.
- `H` (или `/handoff`): модель пишет записку о сессии, она сохраняется в `.cache-keeper/handoffs/`. Если `RU` от 50%, записка пишется по-русски вместе с заголовками («Где начали», «Решения и что сделано», «Открытые вопросы», «С чего продолжить»); шаги для кнопок находятся по «С чего продолжить» или «Pick up here».
- Если рабочая папка — git-репозиторий (есть `.git`), мод дописывает `.cache-keeper/` в `.git/info/exclude` (локальный список исключений, в коммиты не попадает); если туда писать нельзя (например, worktree), — в `.gitignore`.
- В записку мод сам добавляет блок «Repo state» из git: ветка (с ahead/behind), последний коммит, число и список незакоммиченных файлов (до 30). В файле блок на момент записки, в сообщении при продолжении (`C`) — свежий, на момент продолжения. Не репозиторий — блока нет.
- Время последнего ответа мод помнит между сессиями (`$.store`, до 20 последних сессий): после `--resume` полоса показывает реальное тепло кэша (`warm 40m` или `cache cold`), а не `cache ?`. После `/clear` и в новой сессии кэш другой, там `cache ?` верно.
- Когда сохраняется новая записка, старые удаляются из `.cache-keeper/handoffs/` (остаются `keepHandoffs` самых новых, по умолчанию одна). У модов нет удаления файлов, поэтому используется `del` (Windows) или `rm`.
- `C` (или `/handoff continue`): очищает сессию (`/clear`) и продолжает по записке.
- Пункты «Pick up here» из записки становятся кнопками `1`–`3`: выбор очищает сессию и начинает с него. Шаг длиннее 70 символов обрезается на кнопке, а при наведении над ним всплывает карточка с полным текстом.
- Кнопки `handoff` и `clear and continue` стоят отдельной строкой над полосой, чтобы текст полосы не переносился.
- Подсказка «context is heavy» появляется, когда кэш остыл и контекст больше `warnPercent` окна, либо больше `urgentPercent` независимо от кэша.
- Строка под полосой (одна, самая важная; пропадает, когда записка уже сохранена):
  - `cache cools in 8m: press H now…` — за `soonMinutes` минут до остывания (если контекст от 20k токенов): записку дёшево сделать, пока кэш тёплый;
  - `cache is cold: your next message re-writes ~470k tokens` — кэш остыл, и вот сколько токенов придётся записать заново;
  - при тяжёлом контексте то же вместе с призывом «H, потом C».
- Цвета: контекст — жёлтый от `warnPercent`, красный от `urgentPercent`; лимиты `5h`/`week` — жёлтый от 70%, красный от 90%.

Настройки: `ttlMinutes` (60), `soonMinutes` (10), `warnPercent` (60), `urgentPercent` (80), `keepHandoffs` (1).

Установка (в Claude Code, две команды):

```
/plugin marketplace add almunkonst/mods
/plugin install cache-keeper@mods
```

То же из терминала: `claude plugin marketplace add almunkonst/mods`, затем `claude plugin install cache-keeper@mods` (настройки можно сразу задать флагом, например `--config soonMinutes=15`). После установки или обновления — `/reload-plugins`.
